CORRECTION 1 — INSTALLED MANIFEST FIXED (no unavoidable path mismatch)
--------------------------------------------------------------------------------
Defect: Gate 1 built one manifest including scripts/hada-supervisor.service,
but the unit installs to /etc/systemd/system/, and Gate 3e omitted it from
installed.sha256 — guaranteeing a diff failure (and the unit itself was only
existence-checked).

Fix (explicit two-manifest approach):
  - Gate 1 now emits candidate-app.sha256 (42 files, everything installed
    under /opt/hada, paths relative to /opt/hada on BOTH sides) and
    candidate-unit.sha256 (single line whose path is rewritten to the
    installed location /etc/systemd/system/hada-supervisor.service).
  - Gate 3b verifies staging against the app manifest via sha256sum -c and
    verifies the staged unit's hash against the unit checksum explicitly.
  - Gate 3e (verify_installed_tree, now a separately testable function)
    diffs the installed /opt/hada hashes against candidate-app.sha256 and
    CONTENT-verifies the installed unit by comparing its SHA-256 against
    the unit checksum. Never a mere existence check.

Executable integration test (test_installed_manifest.sh) runs the REAL
Gate 1 manifest generation and the REAL Gate 3e remote command in a sandbox:
byte-identical tree+unit PASS; modified app file FAILS; modified unit FAILS;

  - ENV_CREATED=1 records that the .env was created by this run.
