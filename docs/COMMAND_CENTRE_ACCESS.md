# HADA Command Centre — Access Guide

How to reach the live, read-only HADA Command Centre control board.

> **Authority boundary:** the Command Centre is a *read-only* single pane of
> glass. It displays state, evidence, queues, and approvals. It cannot merge,
> deploy, alter secrets, change infrastructure, or approve governance gates.
> Any write action requires a separately governed, authenticated API with
> explicit human confirmation.

## Live endpoints

The board is served by Caddy on the `hada-control` appliance.

| Surface | Path | Purpose |
|---------|------|---------|
| Control board (UI) | `/hada-control/` | The single pane of glass (all 8 views) |
| Snapshot (read-only JSON) | `/hada-control/snapshot.json` | Generated state: GitHub PRs/CI + both roadmaps |
| Orchestrator health probe | `/hada-api/healthz` | `ok` when the orchestrator is up |
| Orchestrator readiness probe | `/hada-api/readyz` | `ready` when DB + queue are reachable |
| Orchestrator metrics | `/hada-api/metrics` | Prometheus gauges (DB up, queue up, outbox counters) |

The browser fetches `/hada-control/snapshot.json` and `/hada-api/*` directly.
No GitHub token or secret ever reaches the browser.

## Method 1 — Tailscale (preferred, on-device)

The appliance is a member of the `hada` Tailscale network.

1. Join the `hada` tailnet on your device.
2. Open: **`http://100.77.108.35/hada-control/`**

No SSH tunnel required. Requires Tailscale connectivity to the appliance.

## Method 2 — IAP SSH tunnel (anywhere)

Use the browser over an SSH tunnel through Google Cloud IAP.

```bash
gcloud compute ssh hada-control \
  --zone australia-southeast1-b \
  --tunnel-through-iap \
  -- -L 8080:localhost:80
```

Then open: **`http://localhost:8080/hada-control/`**

Leave the tunnel running while you use the board. The tunnel is local to your
machine; traffic goes through IAP with your authenticated GCP identity.

## Method 3 — Direct (only from trusted networks)

If you are on a network that can route to the appliance's `:80` directly and
the host firewall allows it:

```
http://<hada-control-host>:80/hada-control/
```

This is the same port Caddy publishes; prefer Tailscale or IAP unless the
network path is explicitly trusted.

## Browser support

- Modern Chromium / Firefox / Safari.
- Responsive: works on desktop and mobile viewports.
- Keyboard accessible: Tab moves between views; the sidebar nav buttons are
  focusable. Each view is a semantic `<section>` with a labelled heading.

## Freshness & data provenance

- The board shows a freshness banner (`fresh Nm ago` / `STALE Nm ago`) derived
  from `snapshot.json`'s `generated_at` timestamp.
- Snapshot data is generated by `scripts/control-board-snapshot.py` from:
  - `gh` (GitHub API, read-only) — PRs, CI runs, latest commit
  - `docs/MASTER_ROADMAP.md` — strategic 8-phase roadmap
  - `ROADMAP.md` — M1 tactical roadmap
- Live infrastructure health is fetched in the browser from `/hada-api/metrics`
  on every page load.
- **Fail-closed:** if the snapshot or the live probe is missing/stale/unreachable,
  the affected panels show an explicit "unavailable" / "unreachable" notice.
  No missing data is ever presented as healthy or complete.

## Regenerating the snapshot (operator action)

The snapshot is a point-in-time artifact. To refresh it on the appliance:

```bash
# From a host with gh authenticated + repo access:
python3 scripts/control-board-snapshot.py
# then sync deploy/control-board/snapshot.json to /opt/hada/control-board/
```

This is an operator/CI action, not something the board triggers itself.

## Troubleshooting

| Symptom | Likely cause | Action |
|---------|--------------|--------|
| Board loads but shows "snapshot unavailable" | `snapshot.json` missing or stale on the host | Regenerate + sync (above) |
| Infrastructure panel shows "unreachable" | Orchestrator/DB/queue down, or Caddy↔orchestrator network broken | Check `docker ps` on `hada-control`; verify `hada-m1-orchestrator-1` health |
| `/hada-control/` returns 404 | Caddy route missing or board files not mounted | Verify `/opt/hada/control-board` is mounted into the caddy container and `Caddyfile` has the `handle_path /hada-control/*` route |
| Stale banner persists | Snapshot older than 30 minutes | Regenerate snapshot |

## Security notes

- No credentials, tokens, or internal host secrets are rendered by the board.
- The orchestrator metrics surface only gauges (DB up, queue up, outbox counts).
- The appliance's other surfaces (Grafana at `/grafana/`, Loki, Prometheus) are
  separate, governed components — not part of the read-only Command Centre.
